# Data Model: Digital Twin Simulation (Gazebo & Unity)

## Entities Overview

This document describes the key data structures and entities for the Digital Twin simulation system that integrates Gazebo for physics simulation and Unity for high-fidelity rendering.

## Digital Twin Environment

**Description**: Represents the virtual space containing both physics simulation and rendering components with synchronized states.

**Fields**:
- id: Unique identifier for the environment
- name: Human-readable name of the environment
- description: Text description of the environment
- creation_date: Timestamp when the environment was created
- update_date: Timestamp when the environment was last modified
- physics_config: Configuration parameters for Gazebo physics simulation
- rendering_config: Configuration parameters for Unity rendering
- environment_objects: Collection of objects in the environment (obstacles, static objects, etc.)

**Relationships**:
- Contains multiple Robot Model entities
- Contains multiple Environmental Property entities

**Validation rules**:
- Name must be unique within the system
- Physics and rendering configs must be compatible
- Environment objects must have valid physics and visual representations

## Robot Model

**Description**: Represents a physical robot with all associated sensors, kinematic properties, and dynamic behaviors.

**Fields**:
- id: Unique identifier for the robot
- name: Human-readable name of the robot
- model_type: Type/classification of the robot
- urdf_path: Path to the URDF file for physics simulation in Gazebo
- unity_model_path: Path to the Unity 3D model for rendering
- position: 3D coordinates in the environment
- orientation: 3D orientation (roll, pitch, yaw)
- kinematic_properties: Physical properties for movement simulation
- dynamic_behaviors: Programming for robot actions

**Relationships**:
- Contains multiple Sensor Data Stream entities
- Connected to Digital Twin Environment entity

**Validation rules**:
- URDF and Unity model must represent the same robot
- Position must be within valid bounds of the environment
- Kinematic properties must be physically plausible

## Sensor Data Stream

**Description**: Represents the continuous flow of sensor readings from simulated sensors that mimics real sensor outputs.

**Fields**:
- id: Unique identifier for the sensor stream
- robot_id: Reference to the robot this sensor belongs to
- sensor_type: Type of sensor (LiDAR, depth camera, IMU, etc.)
- sensor_name: Human-readable name for the sensor
- sensor_position: Position of the sensor on the robot
- sensor_orientation: Orientation of the sensor on the robot
- data_format: Format of the sensor data
- data_frequency: Frequency at which data is generated
- data_stream: Actual sensor data (point clouds, images, acceleration values)

**Relationships**:
- Belongs to Robot Model entity
- Generated by Digital Twin Environment entity

**Validation rules**:
- Sensor type must match the data format
- Data frequency must be within realistic range for the sensor type
- Data values must be within realistic sensor range

## Environmental Properties

**Description**: Defines physical characteristics of the simulated world including gravity, material properties, lighting conditions, and spatial layout.

**Fields**:
- id: Unique identifier for the environmental properties
- environment_id: Reference to the environment these properties apply to
- gravity: Gravity vector (x, y, z components)
- friction_coefficients: Material friction properties
- air_resistance: Air resistance parameters
- lighting_conditions: Parameters for lighting in Unity
- spatial_layout: 3D layout of the environment
- physical_boundaries: Physical boundaries of the environment

**Relationships**:
- Belongs to Digital Twin Environment entity

**Validation rules**:
- Gravity values must be physically plausible
- Friction coefficients must be positive values
- Lighting conditions must be valid for Unity rendering

## State Synchronization

**Description**: Represents the synchronization state between Gazebo physics simulation and Unity rendering.

**Fields**:
- id: Unique identifier for the synchronization state
- environment_id: Reference to the environment being synchronized
- last_sync_timestamp: Time of last synchronization
- sync_status: Current status of synchronization (synced, desynced, delayed)
- physics_state_hash: Hash of physics state at last sync
- rendering_state_hash: Hash of rendering state at last sync
- desync_detected: Flag indicating if desync has been detected

**Relationships**:
- Belongs to Digital Twin Environment entity

**Validation rules**:
- Sync status must be consistent with actual system state
- Timestamps must be reasonable (not in the future)
- Hash values must be properly computed

## Simulation Parameters

**Description**: Represents adjustable parameters for the simulation that can be modified during operation.

**Fields**:
- id: Unique identifier for the parameter set
- environment_id: Reference to the environment these parameters apply to
- physics_step_size: Time step size for physics simulation
- rendering_frame_rate: Target frame rate for rendering
- sensor_update_frequency: Update frequency for sensor data
- real_time_factor: Speed multiplier for simulation time
- collision_detection_settings: Settings for collision detection

**Relationships**:
- Belongs to Digital Twin Environment entity

**Validation rules**:
- All parameters must be within valid ranges for the simulation
- Real time factor must be positive
- Frame rates must be achievable with available hardware
